# euv-app

- GitHub: <https://github.com/euv-dev/euv-app>
- crates.io: _not published_ (no `euv_app` crate on crates.io — the Rust crate lives at `src-tauri/Cargo.toml` as `euv-app` v0.1.0 and is consumed only by the Tauri build)
- docs.rs: _not published_ (the Tauri lib uses `name = "euv_lib"` but is `cdylib + rlib`, not published)

> Tauri 2.x shell that wraps the **euv** web framework as an installable Android APK. Not a Rust library distributed via crates.io — it's a packaging + native-bridge project.

## Build

```sh
cd D:\code\euv-app

# install JS deps once
npm install

# warm bundled-cache (optional but recommended for offline)
node scripts/prefetch-cache.js

# apply runtime config to dist/
node scripts/apply-config.js

# release Android APK
npm run build:android
# → ./euv.apk

# debug Android APK
npm run build:android:debug

# generate icons
npm run icons

# open Tauri devtools
npm run tauri dev
```

`build.sh android release` is the underlying entry — invokes `tauri build --target android --release` plus the JNI/gen scaffolding.

## Fresh-clone build (PR #7, 2026-09-12)

`git clone` → `./build.sh android release` works on a bare Linux host. `build.sh` self-bootstraps in order: rustup Android targets (4 ABIs, idempotent add) → `npm ci` if `node_modules` missing (falls back to `npm install`) → JDK via `scripts/setup-sdk.sh jdk` → Android SDK+NDK via `scripts/setup-sdk.sh android` → page prefetch (inside Tauri `beforeBuildCommand`: `prefetch-cache.js && apply-config.js`) → `tauri android build` → gradle. Verified with a real clone producing a signed 14 MB `euv.apk`.

Pitfalls hit while making this work (all fixed in PR #7):

- **`npm ci` aborts with EUSAGE on old lockfiles** — lockfile generated by an old npm / different platform lacks `@tauri-apps/cli`'s per-platform optional deps (`cli-linux-x64-gnu` etc.). Fix = `npm install --package-lock-only` to regenerate, plus `npm ci || npm install` fallback in build.sh.
- **Dead registry URLs in lockfiles** — `package-lock.json` / `yarn.lock` had `resolved` URLs pinned to a dead internal mirror (`r.npm.sankuai.com`); `npm --package-lock-only` preserves old `resolved` entries, so regenerating alone doesn't fix them. Rewrite to `https://registry.npmjs.org/<name>/-/<file>.tgz` with sed.
- **`src-tauri/gen/android/app/src/main/java/com/euv/generated/` is gitignored** (`app/.gitignore: /src/main/**/generated`) but `RustWebViewClient.kt` (custom-protocol cache interceptor) and `RustWebView.kt` carry local customizations — a fresh clone missed them and would have built an APK **without the cache layer**. Fix = ignore the dir *contents* (`generated/*`) + negations for the two files, and commit them. build.sh still backs up / restores them around `tauri android build` (which regenerates the dir).
- **`npm install` mutates `yarn.lock` / `package-lock.json` in the working tree** even when the install content is identical (registry rewrites `resolved` ordering). Any commit on the project MUST `git checkout HEAD -- yarn.lock package-lock.json` before `git add`, or the diff pollutes the PR. PR #13 first push tripped this; recovered by checking out HEAD then committing only `README.md`.

## README + LICENSE (PR #13, 2026-09-13)

The repo ships **no LICENSE or README** by default — euv-app is a packaging project, not a published crate. When adding them:

- **LICENSE**: copy verbatim from upstream [euv LICENSE](https://github.com/euv-dev/euv/blob/master/LICENSE) (`MIT License / Copyright (c) 2024 euv-dev organization / 21 lines`). Don't rewrite — the file IS the grant, byte-equality matters.
- **README format**: align to the [euv README](https://github.com/euv-dev/euv/blob/master/README.md) skeleton — `<center>` title + image + 3 badges + `</center>` + Api/Download link + one-line description (`>` blockquote) + `## Installation` (npm commands) + `## License` (point to `./LICENSE`) + `## Contributing` + `## Contact` (mailto `root@ltpp.vip`). **Do NOT add** `## What it is` / `## Project layout` / `## Build` trees — the user explicitly rejected long README forms on euv-app PR #13 ("格式参考euv项目的...不需要目录说明"). Scope creep = PR redo.
- **Badges**: 3 slots only. Prefer shields.io for stability. GitHub Actions workflow badges (`workflows/<name>/badge.svg`) intermittently return "not found" in some browsers/network conditions — replaced by release/latest on PR #14. Allowed: `github/release/<owner>/<repo>/latest.svg` + `crates/l/euv.svg` (points to local `./LICENSE`, badge is euv-themed) + 1 PNG `<img src="https://ltpp.vip/github/pages/docs-pages/pages/img/euv.png" height="160">`.
- **License badge URL**: use `https://img.shields.io/crates/l/euv.svg` (matches euv README and keeps shield theme consistent), not `github/license/...` (only useful if repo has its own LICENSE on master; here it does, but the badge style is uglier).

## PR topology (Track 2 fork + PR — verified PR #13 / #14)

Repo layout (this user's environment):

- `origin` → `euv-dev/euv-app` (the upstream where PRs target)
- `fork` → `eastspire/euv-app` (user's fork; confusingly GitHub shows `fork:false` for the user's repo because the address ends up identical to upstream on this host — but PRs do flow correctly)
- Branch must be pushed to **origin** (not fork) to open a PR. `git push fork <branch>` succeeds silently but `gh pr create --head eastspire:<branch>` then errors with `Head repository can't be blank` because GitHub can't resolve the fork as a real fork.

**Correct flow** (used successfully for PR #13 + PR #14):

```sh
git checkout -b <branch> origin/master
# ... edit ...
git checkout HEAD -- yarn.lock package-lock.json   # if npm install ran
git add <only-changed-files>
git commit -m "..."
git push origin <branch>
gh pr create --repo euv-dev/euv-app --head <branch> --base master --title ... --body ...
```

REST fallback (`gh api -X POST repos/euv-dev/euv-app/pulls -f head=eastspire:<branch>`) fails with `422 invalid head` for the same reason — `eastspire:` qualifier doesn't resolve. **The trick**: just push the branch to origin and use a bare branch name (no `eastspire:` prefix) for `--head`. That's the only form that survives gh's head resolution.

After PR merge, delete the local branch: `git checkout master && git branch -D <branch>`.
- **Small-host OOM** (3.5 GB RAM): cap cargo parallelism with `CARGO_BUILD_JOBS=2`, keep the committed gradle.properties JVM caps, and `sync && echo 3 > /proc/sys/vm/drop_caches` before building. Gradle ABI task names are `compileArmReleaseKotlin` / `compileUniversalReleaseKotlin` (`compileReleaseKotlin` is ambiguous in `:app`).

## Native bridge (`src-tauri/src/bridge/`)

Tauri exposes JS-callable Rust functions via the bridge module. Files are split by Rust keyword: `const.rs` / `enum.rs` / `fn.rs` / `impl.rs` / `mod.rs`. The bridge is invoked from the euv frontend via `@tauri-apps/api`'s `invoke()`.

```rust
// src-tauri/src/bridge/mod.rs
#[tauri::command]
pub fn open_external_url(url: String, opener: tauri::AppHandle) -> Result<(), String> {
    tauri_plugin_opener::open_url(url, None::<&str>).map_err(|e| e.to_string())
}
```

Frontend usage:

```js
import { invoke } from '@tauri-apps/api/core';
await invoke('open_external_url', { url: 'https://euv.dev' });
```

## Cache (`src-tauri/src/cache/`)

Pre-fetched asset cache loaded from `bundled-cache/` at startup. Files split by Rust keyword: `const.rs` / `enum.rs` / `fn.rs` / `impl.rs` / `static.rs` / `struct.rs` / `type.rs`. Paired with `scripts/prefetch-cache.js` which downloads assets ahead of time so the APK can run offline.

## Immersive safe-area injection (euv-app PR #4)

The app runs **edge-to-edge immersive** (do NOT disable it — the page genuinely renders under the Android status bar). Since the served page comes from the remote cache (`remote.url = https://ltpp.vip/euv` via the `euv.localhost` custom protocol), the app cannot rely on the page HTML to declare immersion — it injects a script instead:

- Injection point: `src-tauri/src/cache/fn.rs` — `IMMERSIVE_SAFE_AREA_SCRIPT` evaluated via `Builder::on_page_load(PageLoadEvent::Started)` → `webview.eval` (same channel as `LINK_INTERCEPTOR_SCRIPT`, both fired from `inject_page_scripts`).
- The script: sets `window.__EUV_IMMERSIVE__ = true`; ensures the viewport meta contains `viewport-fit=cover` (required for `env(safe-area-inset-top)` to report real insets in the WebView — the public template intentionally omits it for letterbox browsers, PR #59); measures the real top inset with a probe and writes it to `<html>` as `--euv-mobile-safe-top`; and injects a `#euv-immersive-compat` stylesheet (`!important`) so older cached pages built with euv-ui ≤ 0.18.11 (whose header does not consume the var) still get the top padding.
- Framework side (euv-ui ≥ 0.18.12, euv PR #63): `c_mobile_header` / `c_mobile_nav_drawer` consume `var(--euv-mobile-safe-top, 0px)`; `UseEuvLayout::use_safe_area_fix` detects the `__EUV_IMMERSIVE__` flag / `<meta name="euv-immersive">` and writes the measured env value into the var. Browsers never declare it → default 0 → header always flush to top.

**Rule: the page never trusts `env()` directly; only hosts that know they are immersive declare it.**

**Inset dispatch pitfall (2026-09-12, PR #6)**: 在 WebView 上 `setOnApplyWindowInsetsListener` 会**替换** Chromium 自己的 `onApplyWindowInsets`（该实现负责把系统栏 inset 喂给页面 CSS `env(safe-area-inset-*)`）。listener 里直接 `return insets` = 页面 env() 全变 0 → 所有 safe-area 探针测出 0 → mobile header 吸顶。**必须 call-through**：listener 末尾 `webView.onApplyWindowInsets(insets)` 返回其结果（观察的同时不阻断分发）。同理，发给页面 JS 的 inset 值要除 `displayMetrics.density`（Android inset 是物理像素，CSS var 是 CSS px），WebView layoutParams 的 margin 才用物理像素。

## Log (`src-tauri/src/log/`)

Thin wrapper over `tauri-plugin-log` with custom macros (`log/macros.rs`). Call sites use:

```rust
use euv_lib::log::macros::*;
info!("bridge open_external_url: {}", url);
```

Log output goes to both Android logcat (via tauri-plugin-log) and `dist/logs/` on the device.
