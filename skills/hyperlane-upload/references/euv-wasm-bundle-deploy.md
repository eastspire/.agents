# Deploying euv / Rust-WASM Bundles to ltpp.vip

## The trap (2026-09-01 verified)

`euv build` produces a self-contained JS file (`<crate>_bg.wasm` not
included — embedded as a separate file the JS fetches at runtime via
`new URL('<crate>_bg.wasm', import.meta.url)`). When you upload the
generated artifacts to ltpp.vip, the JS file ends up at one URL and the
WASM at another URL — but the JS still has the literal string
`new URL('euv_example_bg.wasm', import.meta.url)`. At runtime the
browser resolves that relative to the **JS's URL**, producing
`https://ltpp.vip/upload/file/{JS_PATH}/euv_example_bg.wasm`, which
404s.

Symptom on the live page: blank body, no JS errors in the console
(404 on a `fetch()` is logged but doesn't throw), Playwright reports
`document.body.innerHTML === ''`.

## Fix: rewrite the wasm URL before uploading the JS

Two upload passes:

1. **Pass 1** — upload the leaf (WASM), upload the JS unmodified.
   Capture both URLs.
2. **Edit** the JS to replace `new URL('<crate>_bg.wasm', import.meta.url)`
   with the literal WASM ltpp.vip URL as a string. Save the rewritten
   copy to `/tmp/<crate>_rewritten.js`.
3. **Pass 2** — upload the rewritten JS. Now it has the absolute URL
   baked in, and `import.meta.url` is never consulted.

```bash
WASM_URL=$(node upload.js www/pkg/<crate>_bg.wasm | jq -r '.[0].url')
JS_URL=$(node upload.js www/pkg/<crate>.js          | jq -r '.[0].url')

# Edit: replace the relative URL with the absolute one
cp www/pkg/<crate>.js /tmp/<crate>_rewritten.js
sed -i "s|new URL('<crate>_bg.wasm', import.meta.url)|\"$WASM_URL\"|" \
  /tmp/<crate>_rewritten.js

# Upload the rewritten JS
node upload.js /tmp/<crate>_rewritten.js | jq -r '.[0].url'
```

The HTML entry point is uploaded last, with `<script type="module"
src="...">` rewritten to the rewritten-JS URL.

## Why two passes (not just rewrite + upload the rewritten JS first)

The first upload needs the JS to exist on a URL so we have its URL to
bake into the rewrite. But the **first** copy uploaded is also
discardable — only the **rewritten** copy is the real one. We don't
delete the first copy from ltpp.vip because ltpp.vip has no public
delete API and the orphan URL is harmless (no one references it).

## euv-cli doesn't produce `euv.js` / `euv_bg.wasm`

Even though the README example references `euv.js` + `euv_bg.wasm`,
`euv build` only emits the user-crate bundle (e.g. `euv_example.js` +
`euv_example_bg.wasm`). The euv framework runtime is inlined into
`<crate>_bg.wasm` (the WASM binary contains everything; the JS is just
the wasm-bindgen glue).

If you see `www/pkg/` retaining old `euv.js` / `euv_bg.wasm` files,
those are from a prior manual upload and are not regenerated by
`euv build`. The `www/pkg/.gitignore` (1-byte file) only ignores itself
— it doesn't keep your repo from committing the `pkg/` directory at
the example crate root (one level above `www/`).

**To avoid committing stray pkg/ at example/ root**: add
`pkg/` to `example/.gitignore` (or rely on `euv build` going straight
to `www/pkg/` and not creating `pkg/`).

## Verify the rewrite landed

```bash
# The rewritten JS should contain the full ltpp.vip URL string
grep -c "https://ltpp.vip/upload/file/" /tmp/<crate>_rewritten.js
# Expect: 1

# The unmodified JS should NOT contain any ltpp.vip URL
grep -c "https://ltpp.vip/upload/file/" www/pkg/<crate>.js
# Expect: 0
```

## End-to-end Playwright probe of the deployed bundle

```python
import asyncio
from playwright.async_api import async_playwright

async def probe(html_url, theme="dark"):
    async with async_playwright() as p:
        b = await p.chromium.launch(
            executable_path="/root/LTPP-MINIMAX/chrome-linux/chrome",
            args=["--no-sandbox", "--disable-dev-shm-usage"],
        )
        c = await b.new_context(viewport={"width": 1280, "height": 900},
                                color_scheme=theme)
        page = await c.new_page()
        errors = []
        page.on("pageerror", lambda e: errors.append(str(e)))
        resp = await page.goto(html_url, wait_until="networkidle", timeout=60000)
        await page.wait_for_timeout(3000)
        print(f"[{theme}] title={await page.title()!r}, "
              f"body_len={await page.evaluate('() => document.body.innerHTML.length')}, "
              f"errors={errors}")
        await page.screenshot(path=f"/tmp/deploy-{theme}.png", full_page=False)
        await b.close()

asyncio.run(probe(INDEX_URL, "dark"))
asyncio.run(probe(INDEX_URL, "light"))
```

Expected: `title` non-empty, `body_len` non-zero, `errors == []`,
screenshots show real content. If `body_len == 0`, the wasm URL
rewrite is wrong — re-check the sed pattern landed.

## Hash-routed SPAs: append `#/path` to the same entry URL

The same `index.html` URL is the entry for every route. To probe the
modal page on the euv example:

```
<INDEX_URL>#/modal
```

The framework reads `window.location.hash` and renders the matching
page. No per-route deploys needed.

## Reference pitfall: ltpp.vip `/euv/` short alias is dead

`https://ltpp.vip/euv/` returns HTTP/2 200 with `content-length: 0`
(empty body) since at least 2026-08-30. The path exists in DNS but
no longer points to a live site. **Always deploy via the upload/file
URL**, not via the `/euv/` short alias. Memory entry:
"ltpp.vip 静态服务怪癖(2026-08-30 实测)".
